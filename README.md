프로젝트 전체 분석 결과

제가 확인한 **Young Buddha Web** 프로젝트의 전체적인 구조와 특징을 요약해드리겠습니다:

### 🏗️ 프로젝트 아키텍처

**백엔드 (Rust + Axum)**

- **웹 프레임워크**: Axum 0.7
- **데이터베이스**: SQLite (rusqlite)
- **캐싱**: Redis (선택적)
- **인증**: JWT + Google OAuth
- **보안**: CSRF 보호 (Double Submit Cookie)

**프론트엔드 (Next.js 14 + TypeScript)**

- **프레임워크**: Next.js 14.2.5
- **스타일링**: Tailwind CSS 4
- **인증**: 미들웨어 기반 JWT 검증
- **타입**: TypeScript 5.9

### 📁 주요 디렉토리 구조

```
young-buddha-web/
├── backend/                 # Rust 백엔드
│   ├── src/
│   │   ├── api/            # API 핸들러
│   │   ├── auth/           # 인증 관련
│   │   ├── db/             # 데이터베이스
│   │   ├── routes/         # 라우트 정의
│   │   ├── services/       # 비즈니스 로직
│   │   └── types/          # 타입 정의
│   └── Cargo.toml
├── frontend/               # Next.js 프론트엔드
│   ├── src/
│   │   ├── app/           # App Router
│   │   ├── components/    # 재사용 컴포넌트
│   │   └── lib/          # 유틸리티
│   └── package.json
└── docker-compose.yml     # Docker 구성
```

### 🔧 주요 기능

1. **인증 시스템**
   - Google OAuth 2.0 연동
   - JWT 기반 세션 관리
   - CSRF 보호 구현
   - 역할 기반 접근 제어 (관리자/일반 사용자)

2. **데이터 관리**
   - SQLite 데이터베이스
   - 데이터베이스 요청 관리 기능
   - 사용자 토큰 저장

3. **보안 기능**
   - CORS 설정
   - CSRF 토큰 검증
   - 환경 변수 기반 구성

4. **프론트엔드 기능**
   - 인증 가드 컴포넌트
   - 관리자 대시보드
   - 미션 관리
   - 결제 시스템

### ⚠️ 현재 상태

- **백엔드**: 기본적인 인증 및 데이터베이스 구조가 구축됨
- **프론트엔드**: 기본 레이아웃과 인증 미들웨어 구현됨
- **사용되지 않는 코드**: 데이터베이스 관련 일부 기능이 현재 사용되지 않음
- **환경 구성**: Docker Compose로 전체 시스템 실행 가능

1. **사용되지 않는 코드 정리**: 데이터베이스 라우트와 타입에서 사용되지 않는 코드 제거
